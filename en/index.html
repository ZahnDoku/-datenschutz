ZahnDoku is purely local software for dental practices. For the patient data processed with the app, the respective user (the dental practice) is the sole controller within the meaning of the GDPR (Art. 4 no. 7). The Provider supplies the software only, does not itself receive any patient data and is not a processor of the user.

2. Core principle: all data stays local

All data captured in the app is stored exclusively locally on the iOS device. No upload to the Provider's servers, cloud services or third parties takes place. The Provider has no access to the data.

3. What data is processed?

  • Patient data: first name, last name, date of birth (optional), notes
  • Photos and videos: dental images for clinical documentation
  • Clinical annotations: VITA shades, lighting type, tooth numbers (FDI scheme)
  • Security data: PIN hash (locally in the Keychain), biometric authentication

Location and device metadata (EXIF/GPS) are automatically removed on capture and not stored.

4. Where is the data stored?

  • Patient data and photos in the protected app sandbox directory (with iOS data protection NSFileProtectionComplete)
  • PIN hash in the iOS Keychain (hardware-encrypted, accessible only on this device)
  • Optional backup in the local file system (visible in the Files app)

Patient data (photos, patient records, trash) is excluded from iCloud/iTunes backups and is not synchronised to the cloud.

5. Device transfer

The app offers a device-transfer function allowing all data to be exported as a .zahntransfer file and moved to a new device. The transfer is carried out solely by the user (e.g. via AirDrop or USB) — without any external server.

The transfer file contains all patient data and is unencrypted. The user is responsible for handling it securely and for deleting it after a successful transfer.

6. Third-party services

ZahnDoku uses no third-party services for data processing:

  • No analytics (no Google Analytics, Firebase, etc.)
  • No crash reporting (no Sentry, Crashlytics, etc.)
  • No advertising tracking
  • No external APIs or servers

7. Subscription and payment

ZahnDoku offers an optional subscription (ZahnDoku Pro). All payment processing is handled exclusively by Apple (App Store / Apple ID). Apple is an independent controller for the payment and account data it processes; Apple's privacy policy applies. ZahnDoku does not receive or store any payment data. The subscription status is evaluated exclusively locally on the device; no personal data is transmitted to the Provider.

8. No data sharing, no international transfer

Patient data is not shared with third parties. The only means of data export is a manual action by the user (ZIP export, PDF report, device transfer, share dialog).

As all data remains exclusively local on the device, no transfer to third countries and no international data transfer takes place.

9. Data security

  • PIN protection (4-digit, hash in Keychain, hardware-encrypted)
  • Optional biometric unlocking (Face ID / Touch ID)
  • iOS data protection (NSFileProtectionComplete) — patient data accessible only when the device is unlocked
  • Automatic removal of location and device metadata (EXIF/GPS) from all photos
  • Patient data excluded from iCloud/iTunes backups
  • Privacy screen in the app switcher (no patient data visible)

10. Deletion

  • Photos and videos can be deleted at any time (7-day trash)
  • Patient data can be completely removed
  • On app uninstallation, all local data is removed

11. Rights of data subjects

Under the GDPR, data subjects have the right to access, rectification, erasure, restriction of processing, data portability and objection.

As all data is stored exclusively locally with the user (the dental practice), these rights are to be exercised against the user as the controller. The Provider cannot process data-subject requests as it has no access to the data.

12. International applicability (UK, Switzerland)

For users and data subjects in the United Kingdom, this policy applies accordingly under the UK GDPR, and for Switzerland under the revised Federal Act on Data Protection (revFADP). The purely local storage concept meets the requirements of these data protection regimes equally.

13. Changes to this privacy policy

The Provider may adapt this policy to reflect changes in the law, case law or app features. The current version linked in the app (see “As of” above) is authoritative.
